# 架构说明

## 会话流程

1. `popup.js` 读取用户主动粘贴的 JSON。`session.js` 检查 128 KiB 输入限制、五段 JWE 格式、头部算法和可选的过期时间。
2. 面板只向后台发送 `sessionToken`。`session-request.js` 核对消息来自本扩展的面板，重新检查 Token 格式，并阻止重叠的导入请求。
3. `browser-session.js` 检查无痕权限和已有无痕窗口，再创建空白无痕窗口，按标签页 ID 找到对应的 Cookie 存储。
4. `session-cookies.js` 生成安全、HttpOnly、无持久化到期时间的 Cookie。长 Token 按 3933 个字符分段。
5. 导航到 ChatGPT 会话页，等待目标 URL 加载完成；页面脚本只返回是否存在用户对象，不将整份会话 JSON传回面板。
6. 验证通过后复用标签页打开 ChatGPT。失败时清理 Cookie、临时状态和新建窗口。关闭受管理窗口时也触发清理。

## 代码边界

- 面板负责输入和反馈，不负责 Cookie 操作。
- 后台入口负责注册事件；请求处理器负责来源校验、单次导入锁和安全错误响应。
- 窗口管理模块通过注入浏览器对象和等待/验证函数完成测试，无需真实 Token。
- JSON 解析只验证结构和时间，不解密 JWE；账号是否有效由 ChatGPT 决定。
- 标签页监听器忽略初始 `about:blank` 的加载事件；成功、超时、导航失败时释放监听器和定时器。

## 已知限制

- 同一浏览器配置文件的无痕窗口共用 Cookie 存储；只允许在没有其他无痕窗口时开始导入。
- 用户之后手动新建无痕窗口时仍会共享该存储，因此不支持在同一配置文件中并行隔离多个账号。
- 清理代码是尽力执行；浏览器崩溃、强制退出等情形依赖浏览器自身的无痕数据生命周期。
- 会话验证接口、Cookie 名称和 Token 结构不是本项目控制的稳定 API。
- 原版保留一个输入面板，不包含订阅管理或付款代码。

## 测试范围

`extension-*.test.js` 覆盖输入解析、Cookie 分段、权限检查、正常导入、回滚清理、请求来源、并发提交及验证页导航失败。其他测试覆盖保留的本地服务。

自动化测试使用浏览器 API 替身，不证明任意时刻的 ChatGPT 网站兼容性。真实浏览器验证应使用自己授权的账号，并避免在日志或测试文件中记录会话凭证。
